### 1.2 功能模块详细说明

#### 1.2.1 用户管理模块
**功能描述**：负责用户的注册、登录、信息管理和权限控制

**主要功能**：
- **用户注册**：新用户注册账号，自动分配查看者角色
- **用户登录**：JWT Token 认证，支持标签页隔离
- **个人信息管理**：修改昵称、邮箱、手机号、头像
- **角色权限管理**：管理员可分配用户角色（ADMIN/EDITOR/VIEWER）

**技术实现**：
- Spring Security + JWT 认证
- BCrypt 密码加密
- SessionStorage 标签页隔离

---

#### 1.2.2 文档管理模块
**功能描述**：文档的全生命周期管理

**主要功能**：
- **文档创建**：创建新文档，自动成为所有者
- **文档编辑**：支持富文本编辑，自动保存
- **文档删除**：仅所有者可删除
- **文档搜索**：按标题和内容模糊搜索
- **文档分享**：设置其他用户的访问权限（VIEWER/EDITOR）
- **文件夹管理**：树形结构组织文档

**技术实现**：
- JPA 实体映射
- 原生 SQL 模糊查询
- 文档权限表（document_permissions）

---

#### 1.2.3 实时协作模块
**功能描述**：多人实时协作编辑核心功能

**主要功能**：
- **多人在线编辑**：多个用户同时编辑同一文档
- **内容实时同步**：500ms 防抖后广播更新
- **在线用户显示**：显示当前编辑文档的所有用户
- **光标位置同步**：显示其他用户的光标位置和用户名

**技术实现**：
- WebSocket + STOMP 协议
- SockJS 降级支持
- Canvas API 计算光标像素位置

---

#### 1.2.4 评论管理模块
**功能描述**：文档评论和讨论功能

**主要功能**：
- **添加评论**：对文档添加评论
- **回复评论**：支持多级回复，形成评论树
- **@提及功能**：在评论中 @其他用户
- **评论树展示**：递归展示评论层级结构

**技术实现**：
- 自关联表结构（parent_id）
- 递归查询构建评论树
- WebSocket 实时推送新评论

---

#### 1.2.5 任务管理模块
**功能描述**：文档相关的任务管理

**主要功能**：
- **任务创建**：在文档中创建任务
- **任务分配**：分配给特定用户
- **任务状态管理**：TODO/IN_PROGRESS/COMPLETED/CANCELLED
- **截止日期管理**：设置和提醒任务截止日期

**技术实现**：
- 任务状态枚举
- 权限控制（仅创建者和被分配者可修改）
- 完成时间记录

---

#### 1.2.6 通知系统模块
**功能描述**：系统消息通知功能

**主要功能**：
- **实时通知推送**：通过 WebSocket 实时推送
- **通知列表查看**：查看所有通知
- **已读标记**：标记通知为已读
- **通知类型管理**：文档分享、评论回复、任务分配等

**技术实现**：
- SimpMessagingTemplate 点对点消息
- 用户专属队列（/user/{userId}/queue/notifications）
- 通知类型枚举

---

#### 1.2.7 系统管理模块
**功能描述**：管理员后台管理功能

**主要功能**：
- **用户管理**：查看、编辑、禁用用户
- **角色分配**：为用户分配或移除角色
- **操作日志查看**：查看系统所有操作记录

**技术实现**：
- @PreAuthorize 权限控制
- 操作日志自动记录
- 分页查询

### 2.3 分层架构详解

#### Controller 层（控制器层）
**职责**：接收 HTTP 请求，参数验证，调用 Service 层，返回响应

**示例**：
```java
@RestController
@RequestMapping("/api/documents")
public class DocumentController {
    @PostMapping
    public ApiResponse<Document> createDocument(@Valid @RequestBody DocumentRequest request) {
        // 1. 接收请求
        // 2. 参数验证（@Valid）
        // 3. 调用 Service
        // 4. 返回响应
    }
}
```

---

#### Service 层（业务逻辑层）
**职责**：实现业务逻辑，权限检查，事务管理，调用 Repository 层

**示例**：
```java
@Service
public class DocumentService {
    @Transactional
    public Document createDocument(DocumentRequest request, Long userId) {
        // 1. 业务逻辑处理
        // 2. 权限检查
        // 3. 调用 Repository 保存数据
        // 4. 创建权限记录
        // 5. 返回结果
    }
}
```

---

#### Repository 层（数据访问层）
**职责**：数据库操作，CRUD，自定义查询

**示例**：
```java
@Repository
public interface DocumentRepository extends JpaRepository<Document, Long> {
    List<Document> findByOwnerIdOrderByUpdatedAtDesc(Long ownerId);
    
    @Query("SELECT d FROM Document d WHERE d.title LIKE %:keyword%")
    List<Document> searchByKeyword(@Param("keyword") String keyword);
}
```

---

#### Security 层（安全层）
**职责**：身份认证，权限控制，JWT 处理

**组件**：
- **JwtAuthenticationFilter**：拦截请求，验证 Token
- **SecurityConfig**：配置安全规则
- **UserDetailsServiceImpl**：加载用户信息

## 3. 主要功能流程

### 3.1 用户登录流程

```
┌──────┐                                              ┌──────┐
│ 前端 │                                              │ 后端 │
└──┬───┘                                              └──┬───┘
   │                                                      │
   │  1. POST /api/auth/login                            │
   │     {username, password}                            │
   ├────────────────────────────────────────────────────>│
   │                                                      │
   │                                  2. 验证用户名和密码 │
   │                                  UserDetailsService │
   │                                                      │
   │                                  3. 生成 JWT Token  │
   │                                  JwtUtil.generate() │
   │                                                      │
   │  4. 返回 Token 和用户信息                           │
   │     {token, id, username, roles}                    │
   │<────────────────────────────────────────────────────┤
   │                                                      │
   │  5. 保存 Token 到 sessionStorage                    │
   │     sessionStorage.setItem('token', token)          │
   │                                                      │
   │  6. 后续请求携带 Token                              │
   │     Authorization: Bearer {token}                   │
   ├────────────────────────────────────────────────────>│
   │                                                      │
   │                                  7. 验证 Token       │
   │                                  JwtAuthFilter      │
   │                                                      │
   │  8. 返回数据                                        │
   │<────────────────────────────────────────────────────┤
   │                                                      │
```

**流程说明**：
1. 用户输入用户名和密码，前端发送登录请求
2. 后端验证用户名和密码（BCrypt 比对）
3. 验证成功后生成 JWT Token（有效期 24 小时）
4. 返回 Token 和用户基本信息给前端
5. 前端保存 Token 到 sessionStorage（实现标签页隔离）
6. 后续所有请求在 Header 中携带 Token
7. JwtAuthenticationFilter 拦截请求并验证 Token
8. 验证通过后返回数据

### 3.2 文档创建流程

```
┌──────┐                                              ┌──────┐
│ 前端 │                                              │ 后端 │
└──┬───┘                                              └──┬───┘
   │                                                      │
   │  1. POST /api/documents                             │
   │     {title, content, folderId, tags}                │
   ├────────────────────────────────────────────────────>│
   │                                                      │
   │                                  2. 验证 Token       │
   │                                  JwtAuthFilter      │
   │                                                      │
   │                                  3. 检查用户角色     │
   │                                  需要 EDITOR 角色   │
   │                                                      │
   │                                  4. 创建文档记录     │
   │                                  DocumentService    │
   │                                                      │
   │                                  5. 创建权限记录     │
   │                                  OWNER 权限         │
   │                                                      │
   │                                  6. 保存到数据库     │
   │                                  @Transactional     │
   │                                                      │
   │  7. 返回文档信息                                    │
   │     {id, title, content, owner, createdAt}          │
   │<────────────────────────────────────────────────────┤
   │                                                      │
   │  8. 跳转到文档编辑页面                              │
   │     /documents/{id}                                 │
   │                                                      │
```

**流程说明**：
1. 用户填写文档信息，点击创建
2. 后端验证 JWT Token
3. 检查用户是否有 EDITOR 或 ADMIN 角色
4. 创建文档记录（Document 表）
5. 自动创建 OWNER 权限记录（DocumentPermission 表）
6. 事务提交，保存到数据库
7. 返回创建成功的文档信息
8. 前端跳转到文档编辑页面

### 3.3 实时协作编辑流程

```
┌────────┐              ┌──────┐              ┌────────┐
│ 用户A  │              │ 后端 │              │ 用户B  │
└───┬────┘              └──┬───┘              └───┬────┘
    │                       │                      │
    │  1. 打开文档          │                      │
    │  建立 WebSocket 连接  │                      │
    ├──────────────────────>│                      │
    │                       │                      │
    │  2. 订阅文档频道      │                      │
    │  /topic/document/{id} │                      │
    ├──────────────────────>│                      │
    │                       │                      │
    │                       │  3. 用户B也打开文档  │
    │                       │  建立连接并订阅      │
    │                       │<─────────────────────┤
    │                       │                      │
    │  4. 用户A编辑内容     │                      │
    │  防抖 500ms           │                      │
    │                       │                      │
    │  5. 发送内容更新      │                      │
    │  /app/document/{id}/content                 │
    ├──────────────────────>│                      │
    │                       │                      │
    │                       │  6. 广播给所有订阅者 │
    │                       ├─────────────────────>│
    │                       │                      │
    │                       │  7. 用户B收到更新    │
    │                       │  刷新编辑器内容      │
    │                       │                      │
    │  8. 用户A移动光标     │                      │
    │  计算像素位置         │                      │
    │                       │                      │
    │  9. 发送光标位置      │                      │
    │  /app/document/{id}/cursor                  │
    ├──────────────────────>│                      │
    │                       │                      │
    │                       │  10. 广播光标位置    │
    │                       ├─────────────────────>│
    │                       │                      │
    │                       │  11. 用户B显示光标   │
    │                       │  显示用户名标签      │
    │                       │                      │
```

**流程说明**：
1. 用户A打开文档，建立 WebSocket 连接
2. 订阅文档频道 `/topic/document/{id}`
3. 用户B也打开同一文档，建立连接并订阅
4. 用户A编辑内容，前端防抖 500ms
5. 发送内容更新到服务器
6. 服务器广播给所有订阅该文档的用户
7. 用户B收到更新，自动刷新编辑器内容
8. 用户A移动光标，使用 Canvas API 计算像素位置
9. 发送光标位置到服务器
10. 服务器广播光标位置
11. 用户B显示用户A的光标和用户名标签

## 4. 数据流转图

```
前端 → Axios → HTTP Request → Controller → Service → Repository → Database
                                    ↓           ↓          ↓
                                  验证参数   业务逻辑   数据操作
                                    ↓           ↓          ↓
前端 ← JSON ← HTTP Response ← Controller ← Service ← Repository ← Database
```

```
用户A → WebSocket Client → STOMP → WebSocketController → MessageBroker
                                                              ↓
                                                         广播消息
                                                              ↓
用户B ← WebSocket Client ← STOMP ← MessageBroker ← 订阅频道
```

## 5. 安全机制

### 5.1 认证流程
```
请求 → JwtAuthenticationFilter → 提取 Token → 验证 Token → 设置 Authentication
                                      ↓
                                  Token 无效
                                      ↓
                                返回 401 错误
```

### 5.2 权限控制
```
请求 → @PreAuthorize 注解 → 检查角色 → 有权限：继续执行
                               ↓
                          无权限：返回 403
```
